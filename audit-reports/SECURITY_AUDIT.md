## Positive controls and boundaries

Passive instrumentation recorded zero HTTP/HTTPS/net/DNS/fetch/child-process calls, no execution of a throwing project source file, unchanged synthetic project hashes, and no fake environment/.env credential in outputs: [passive proof](evidence/security/passive-proof.json). Source review agrees: the tool parses text and checks PATH files without invoking Domo CLI. These are tested controls, not a universal proof of every future path.

Root and fixture traversal, symlink/junction descendants, size bounds and prototype-shaped inputs were exercised. A selected root reached through an ancestor junction is accepted; selecting that root explicitly does not itself demonstrate escaping the selected project. Reads recheck path/file identity; concurrent adversarial filesystem modification is not a fully race-free sandbox guarantee. Exclusive output creation prevents clobbering, but Node path APIs cannot guarantee ancestor stability against a privileged concurrent writer. Scan a stable checkout.

Bounds: 1 MiB per JSON/source file, 32 MiB aggregate source, 50,000 entries, 64 directory levels, 128 JSON/source structural levels, 128 ignore patterns including defaults, 1,024 characters/pattern, eight pattern nesting levels. Oversize/unsupported source is unverified; whole-scan limits are fatal. Promise rule timeouts cannot preempt synchronous parsing. Worker-process isolation remains a defense-in-depth improvement.

An investigated `+(a|aa)` matcher slowdown was **not reproduced** by the exact picomatch matcher and is not reported as a vulnerability. Regex/pattern complexity is partially tested, not exhaustively proved. Redaction recognizes common credential patterns, not arbitrary confidential text. Do not treat generated reports as automatically public-safe.

Live authentication, TLS, tenant isolation, rate limits, retries and API writes are NOT APPLICABLE to this offline implementation. Linux/macOS filesystem semantics and Node20/24 are NOT TESTED locally. Gitleaks/Semgrep/OSV executables were unavailable; no successful local secret scan is claimed. CI secret scanning is configured but unexecuted. npm account 2FA, token permissions, branch protection and package provenance for the new candidate remain unverified.

Published 0.1.0 has no runtime files; these source-level fixes are in the local candidate and are not delivered to npm users yet. See [release assessment](RELEASE_READINESS.md).
